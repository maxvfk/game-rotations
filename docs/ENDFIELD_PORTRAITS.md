# Arknights: Endfield — каталог оригинальных портретов

**Канонический реестр:** [data/portraits/arknights-endfield.json](../data/portraits/arknights-endfield.json)  
**Визуальный каталог:** https://maxvfk.github.io/game-rotations/?portraits=arknights-endfield  
**Локальные изображения:** `public/portraits/arknights-endfield/<operator-id>.png`

## Происхождение и проверка

Источник — **сохранённая пользователем английская страница** `https://endfieldtools.dev/characters/` (MHT, 2026-11-02). Не перечень персонажей из нашей памяти и не имена, полученные вручную из CDN: соответствие взято из пар **ссылка на карточку оператора + `img alt`** в HTML.

В архиве **34 компактных изображения `charicon` PNG**, соответствующих **33 страницам операторов/главного героя**: у Endministrator **две разные иконки (F/M)**. Изображения **оригинальные**, не были заново обрезаны или перерисованы. В исходных данных сохранены exact `sourceImage`, полный `sha256`, `sourcePage` и размеры (ширина 150 px; высота 206–210 px).

**Важно для идентичности:** исходные имена PNG не всегда совпадают с английскими именами: `icon_chr_0032_lizhiyan.png` → **Arcane**, `icon_chr_0007_ikut.png` → **Arclight**, `icon_chr_0004_pelica.png` → **Perlica**. Сопоставляй по `characters[].id/name`, а не угадывай по имени source-image.

У Endministrator используются **только явные ID** `endministrator-f` и `endministrator-m`. Общий `endministrator` не имеет default alias, потому что выбор мужской/женской модели влияет на изображение. **Не заменяй одну другой молча.**

## Использование в новой команде

1. Найди ID и лицо оператора в визуальном каталоге. Кнопка «Копировать путь» возвращает `portraits/arknights-endfield/<id>.png`.
2. В `data/rotations/arknights-endfield/<team>.json` используй точный `characters[].id` и путь из реестра. В `data/catalog.json` путь должен совпадать с book.
3. При создании команды через `npm run team:add -- --spec ...` генератор уже умеет выбирать портреты из `data/portraits/<game>.json`. Для Endfield указывай `id`, `slot`, `investment`; `name` и `portrait` можно не дублировать. **Не нужно снова искать изображения.**
4. **До первой ротации Endfield требуется добавить `data/controls/arknights-endfield.json` с корректными биндами и семантикой**. Наличие портретного каталога не означает, что игровая механика и controls уже исследованы. Статус Endfield в каталоге игр оставляем `planned` до настоящей выбранной ротации.
5. Запусти `npm run validate:portraits`, `npm run validate:data`, `npm run build` и Chromium offline/PWA smoke.

## Отображение

Оригинальные файлы имеют компактный вертикальный формат, а не квадрат. В квадратных карточках мы **не меняем PNG**, а используем CSS:

```css
.operator-portrait {
  width: 160px;
  height: 160px;
  object-fit: cover;
  object-position: center top;
}
```

Таким образом на экране видна голова/плечи, а все пиксели оригинального изображения остаются в исходном файле. При добавлении других игр не применяй это кадрирование автоматически: там могут быть другие пропорции.

## Качество и безопасность

- `scripts/validate-portraits.mjs` проверяет **каждый из 34** PNG: путь ID, 8-байтную сигнатуру PNG, IHDR, размеры, SHA-256, страницу оператора и наличие всех 34 ID.
- `scripts/import-endfield-portraits.mjs` использован для **однократного** импорта по зафиксированным SHA-256. Обычные сборки и офлайн-работа не требуют EndfieldTools или сети; CDN не является каноническим хранилищем файлов сайта.
- Source snapshot — **не** живой ростер, не доказательство владения операторами и не TC/live-kit. Новых персонажей добавлять после отдельной проверки HTML/артов/IDs.
- Портреты и имена принадлежат соответствующим правообладателям; EndfieldTools.DEV — источник сохранённой базы. Атрибуция сама по себе не предоставляет лицензию на распространение; при публичном использовании следить за условиями правообладателей.
