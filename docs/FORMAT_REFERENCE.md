# Формат ротаций v1 — контракт, значения и ограничения

Это **технический справочник** для `data/rotation.schema.json`, `src/rotation-types.ts`, `src/rotation.ts`, `scripts/validate-rotations.mjs`. При расхождении схемы и этого документа — **проверяй живой код**; исправляй документацию/валидатор совместно, не молча обходи ограничения.

## Концепция

`data/catalog.json` показывает карточку; `data/rotations/<game>/<team>.json` хранит действия, варианты и состояние; `data/controls/<game>.json` сопоставляет semantic `input.kind` с устройством. Сборка Vite `import.meta.glob` импортирует JSON, `?team=<team-id>` открывает общий экран, Service Worker кеширует итоговые ассеты. Не нужно создавать HTML для команд.

## Book v1 (обязательные поля)

| Поле | Тип | Назначение |
| --- | --- | --- |
| `schemaVersion` | `1` | Версия контракта, не игры |
| `id`, `game` | kebab-case | Уникальный ID команды, game ID из каталога |
| `title`, `gameVersion` | string | Читаемое имя, точный server/live patch при необходимости |
| `source` | URL | Основной долговечный research guide/источник |
| `verificationNote` | string | Разделение sourced/own adaptation/unknown, видно пользователю |
| `controls` | game-id | Имя `data/controls/<game>.json`, совпадает с `controls.game` |
| `characters[]` | 2–5 | `id, name, glyph, color #RRGGBB, portrait, investment` |
| `defaultSlots` | map | `{character-id: slot-id}`, полное уникальное соответствие |
| `variants[]` | 1+ | `id, label, sub, type, intro, verification, opener[], loop[]` |
| `stages` | map | `{stageId: {person,title,sub,actions,check,extra}}` |

`stageId` — ASCII буквы/цифры с начальной буквой (допустим camelCase); game/team/character/variant ID — lowercase-kebab (несовместим с camelCase). `variants.opener[]` и `loop[]` — упорядоченные **ссылки** на `stages`, не вложенные actions.

**Прогресс:** сайт хранит `mode`, `done:mode-opener|loop`, `at:mode-opener|loop` в localStorage. Варианты и ID команд стабильны: изменяя ID, можно потерять выбранную вкладку/прогресс/избранное. Для текущей WuWa-команды сохранён старый `wuwa-r-v1:` namespace.

## Action и визуальная подсказка

```json
{"text":"Skill · усиленный выпад","tone":"vital","input":{"kind":"skill"}}
```

- `text`: человеческое описание конкретного действия/анимации (не физическая клавиша).
- `tone` `normal|key|vital|swap|flow|sensitive`: оформление карточки; **не** утверждение о верификации.
- `input.kind`: `intro`, `outro`, `swap`, `basic`, `heavy`, `skill`, `ultimate`, `echo`, `dodge`, `auto`.
- `count`: только `basic`, 2–20 последовательных нажатий; `repeat`: только `basic`, неопределённая серия, альтернативный бейдж кнопки.
- `input.press?: "tap"|"hold"`: **необязательный** модификатор только для `skill`. Без него старая схема кнопок не меняется; `tap` оставляет обычное обозначение, `hold` выводит `удерж. E` (ПК), `удерж. △` (PS5), `Hold Skill` (terms). Для последовательных tap→hold с обязательным отпусканием добавь `hint`, не подменяй нажатием `heavy`.
- `optional?: true`: маркирует действие как необязательное без удаления из списка. `condition?: string` разрешено **только с `optional:true`** и показывает заметное «УСЛОВНО / Если: …»; условие — текстовая подсказка, не вычисляется автоматически. `hint?: string` — дополнительное видимое пояснение для одного действия, например отпускание кнопки перед hold. Необозначенные действия остаются обязательными.
- Для выражения **ветвящихся/динамических** ротаций этого недостаточно: `optional/condition` не выполняет автоматических пропусков и не обещает правильную логику ресурсов.

- `target`: **обязателен для `outro` и `swap`**, значение одного из `characters[].id`. Для других действий запрещён; `intro` нажатие определяется `stage.person`.
- `auto`: автоматическое действие после выполнения триггера; не маскируй им неизвестную механику.
- Смысл `outro` — game-specific особая передача, `swap` — обычная смена. Не смешивать.
- `check` — ресурс, окно, условие; `extra` — объяснение/неуверенность. Их надо составлять на основе live mechanics и источников.

**Долг текущего renderer v1:** подписи `R · ...`, `E · ...`, `Death Snip`, `Bloom`, `Feather Fall` имеют точечные WuWa-специфичные сокращения в `src/rotation.ts`. Для новых игр `text` будет отображаться как есть, но семантический бейдж кнопки определяется по `input.kind`. Если требуется новый тип действия/составное нажатие, это отдельное расширение движка — нельзя утверждать, что JSON уже универсален для любых игровых механик.

## Variant и verification

- `id`: стабильное значение, совпадающее с `data/catalog.json` (`variants[].id`).
- `label/sub/type`: заголовок, подзаголовок и категория UI.
- `intro`: объяснение практической цели, ограничения, сложности.
- `loopCaution?: string`: видимое предупреждение **рядом с переключателем «Повтор»**, только при выбранном loop. Добавляй для не проверенного steady-loop, даже если вариант в целом `adapted`. Отсутствие этого поля **не является доказательством** верификации. Для YYXL `2F`/Quickswap и Hsin варианты имеют явные предупреждения.
- `opener`, `loop`: реальные списки этапов. Их различие основано на стартовых ресурсах/баффах; непротестированные loop явно помечать.
- `verification`:
  - `adapted` — основано на sourced route, но адаптировано под аккаунт/практику.
  - `partial` — какая-то граница/условие пока не подтверждена.
  - `experimental` — собственная гипотеза / нереплицированная связка.
  - `verified` — **резервировать только** для конкретной версии и условий с проверенным live-kit, расчётной/TC атрибуцией и фактическим воспроизводимым route (не просто бейдж сайта или один clear). Обязательно изложить evidence в source/guide.
  
Наличие зелёного CI доказывает корректный JSON/сборку, не игровую оптимальность. Метка сайта калькулятора (WuWaLAB или аналог) не переносится автоматически.

## Controls v1

`data/controls/<game>.json`:
```json
{
  "schemaVersion": 1,
  "game": "example-game",
  "schemes": [{
    "id": "terms",
    "label": "A / H",
    "help": [["A", "Basic"], ["Skill", "навык"]],
    "keys": {
      "basic": "A", "heavy": "H", "skill": "Skill",
      "ultimate": "Ult", "echo": "Echo", "dodge": "Dash",
      "auto": "Auto", "repeat": "A · серия"
    },
    "slotKeys": {"1": "", "2": ""},
    "slotExplain": "Универсальные обозначения",
    "summary": "Описание схемы для пользователя"
  }]
}
```

- `schemes[]`: 1+, ID каждой схемы уникален. `pc`/`ps5` — имена по соглашению, не обязательны, но можно добавить при известных биндах.
- `id: "terms"` — специальный режим универсальных терминов, он скрывает слоты и показывает `Intro/Outro/Swap` текстом.
- Остальные схемы используют `slotKeys` и отображают кнопки переключения. Обязательно покрыть значения `defaultSlots`.
- `keys` v1 **обязаны** содержать восемь строк `basic/heavy/skill/ultimate/echo/dodge/auto/repeat` даже если игра не использует один из типов. Неиспользуемые значения можно задать нейтральным `—`, но **не** создавать фиктивные actions.
- `help` — парные элементы `[кнопка, значение]`, `summary` и `slotExplain` — объясняют управление в UI.
- Важно: схема не моделирует сложные комбинации, удержание+условие, статус-комбо/карты как отдельные action kinds без изменения движка.

## Именованные библиотеки изображений

Для WuWa больше не подбирай арт вручную. Каноническая база — `data/portraits/wuthering-waves.json` (61 entry) и локальные файлы `public/portraits/wuthering-waves/<character-id>.webp`. Подробно: [PORTRAITS.md](PORTRAITS.md).

`characters[].portrait` в book и `teams[].characters[].portrait` в каталоге должен совпадать с `portrait` выбранного ID (например, `yyxl → yangyang-xuanling`). Валидатор `npm run validate:portraits` не пропустит несовпадение. Для других игр без готовой библиотеки возможны старые пути `portraits/name.webp`, но предпочтительна именованная папка игры.

## Catalog

В `games[]`: `id`, `name`, `shortName`, `mark`, `accent`, `status` (`available` при наличии команды), `subtitle`, `teams[]`.

`teams[]`: `id`, `name`, `subtitle`, `characters[]`, `status`, `statusDescription`, `gameVersion`, `source`, `variants[]` (каждый `id/name/verification`). Поля source/gameVersion, персонажи и варианты должны совпадать с book. Путь HTML / `path` больше не используется.

## Важные ограничения и правила обновления

- Первую версию schema нельзя расширять несовместимо с текущими данными или ломать сохранённые URI. При необходимости новых kind/controls — обновляй типы, JSON Schemas, валидатор, шаблоны, renderer, UI-тесты и инструкцию **одним PR**.
- Карточка ориентирована на линейную цепочку stages одного активного персонажа. Для ветвления, условных блоков, stack-based decision tree и пошагового card draw v1 недостаточна.
- Для 2–5 персонажей renderer может показать stage, но корректность игровых slot bindings и ресурса в другом жанре нужно проверить в действующей игре.
- Offline/PWA: картинки **локальные**, новый bundle/service worker после merge обновляется браузером. Проверь установленную PWA и deep links отдельно.


## Дополнение к v1: Endfield operator-owned team actions (обратно совместимо)

Для первой выбранной Endfield-команды добавлены новые **семантические** значения `input.kind`: `combo` (вручную активируемое Combo Skill), `final-strike` (завершающий удар полной Basic Attack chain), `finisher` (отдельное действие при Stagger), `dive` (Dive Attack с игровым контекстом). Они **не** эквивалентны `basic` или `auto` и не заменяют игровые triggers.

Добавлено необязательное `input.actor:"character-id"` — владелец именно этого действия. При командных фазах `stage.person` остаётся портретным фокусом карточки, **не** утверждением, что весь этап постоянно контролируется этим оператором. Renderer показывает имя каждого `actor` в подписи. `combo` не подразумевает обычный `swap`; он может исполняться off-field. Валидатор проверяет, что `actor` есть в `book.characters`. Старые WuWa-книги без `actor` показываются без изменений.

В Endfield controls обязательные v1-кнопки остаются, новые `combo/finalStrike/finisher/dive` разрешены как дополнительные поля. Для PC Battle Skill определяется по позиции `actor` (1–4), Ultimate — удержанием этой клавиши; Combo — E. На данном этапе публикуются `terms` и `pc`. **PS5 mapping не публикуем**, пока не проверено разделение operator Skill/Ultimate/Combo и switch inputs на действующем билде.

Для Si обе выбранные ротации `partial`: пользовательский выбор подтверждён, но 0-SP/0-Energy cold start, steady-loop, real animation durations и второй Si Skill **не прошли независимую валидацию**. Два зелёных блока Prydwen подтверждены пользователем по видео Gacha Gamer как **один Tangtang Ultimate → Dive Attack**; `dive` — отдельный input.kind, а не второй `ultimate`. В `loop` помещена одна карточка ресурсного восстановления с предупреждением, а не ложное повторение opener.


### Endfield: BA и Final Strike — единая семантика карточек

Для Endfield `final-strike` обозначает **цель всей цепочки BA до завершающего удара**. Это **не отдельная кнопка после BA** и не дополнительное действие сверх полной цепочки. Кнопка в Terms: `FS`, в PC: `ЛКМ → FS`. При полном завершении цепочки FS активного (controlled) оператора восстанавливает SP, наносит Stagger и может выполнить условия конкретного Combo; FS вне активного управления этого не делает. Источники: [официальный tutorial](https://endfield.games/en/tutorials/battle/), [Prydwen Combat Basics](https://www.prydwen.gg/arknights-endfield/guides/combat-basics).

При описании source rotation не записывай `basic ×N`, если автор ожидает именно Final Strike. Для Xaihi `FS ×2` означает **две завершённые BA-цепочки** активного оператора под соответствующим Battle Skill, а не два удара. `input.kind:"final-strike"` с текстом `×2 · подготовить Xaihi Combo` отображается как **FS | ×2 · ...**; это всё ещё одна UI-карточка с конкретной целью, а не сокрытие двух отдельных BA.

`basic` сохраняется для **промежуточных ударов/заполнения времени** до Combo cooldown, когда завершение цепочки не обязательно. Варианты Maygi/Prydwen для Si теперь применяют одинаковую систему: BA = filler, FS = завершение полной цепочки/условие/ресурс. `finisher` (первый удар по Staggered врагу) и `dive` (удар в прыжке после Ultimate Tangtang) — другие типы.


### Endfield: цвет действия определяется `input.kind`, а не `tone`

В Endfield-карточках `src/rotation.ts` назначает CSS-классы `endfield-action kind-<input.kind>`. Стили определены в `src/rotation.css` и **ограничены Endfield**; WuWa и другие игры продолжают использовать существующие цвета `tone`. Это только оформление и не меняет боевую логику, действия, ресурсы, статусы `verification` и управление.

Палитра, основанная на визуальном кодировании Prydwen, адаптирована для тёмной темы сайта: `skill` — голубой, `combo` — фиолетовый, `final-strike` — кораллово-красный, `ultimate` — зелёный, `finisher` — оранжевый, `dive` — бирюзовый, `basic` — нейтральный серо-голубой, `dodge` — жёлтый. Названия кнопок остаются обязательными: смысл нельзя передавать только цветом. Для дальтонизма и мобильных экранов у карточки также есть цветная левая полоса.


### Endfield: переключатель «Полный / Компактный»

В Team Renderer для Endfield рядом с «Термины / ПК» доступен независимый переключатель плотности **Полный / Компактный**. По умолчанию — полный. Выбор хранится в том же `localStorage` namespace команды как `game-rotations:v2:<team-id>:compact` (JSON boolean), не сбрасывается сменой Maygi/Prydwen, схем управления, First/Loop и перезагрузкой/PWA offline.

`compact-actions` — CSS-модификатор `.rotation-app.game-arknights-endfield`. Внутри каждой Endfield `.action` он скрывает `.action-label`, `.action-hint`, `.action-condition`, `.action-optional`, уменьшает отступы/высоту, **но оставляет** mini 24×24, `.keycap`, цвета типов действий, стрелки и stage `check/extra`, а также полный title и aria-label. В компактном виде два **текстовых блока под цепочкой этапа** (`.checks` из `stage.check` и `.extras` из `stage.extra`) скрываются CSS-селектором `compact-actions .stage-body > :is(.checks,.extras)`, но сохраняются в DOM и полностью возвращаются при выборе «Полный». `loop-warning` и заголовки этапов остаются видимыми. Для сценариев с критичными требованиями к ресурсам следует использовать полный режим; Compact — быстрая памятка. Рендер добавляет `.action-compact-modifier` для `×N` из исходного `action.text` (например, `FS ×2` — две полные BA chains); в полном режиме дополнительный маркер скрыт. Для `optional/condition` показывается компактная сигнальная метка (в Si `Stagger`), полная формулировка остаётся в title/aria-label. `input.press:'hold'`, PC `удерж. 4` и другие keycap modifiers отображаются без изменений.

Компактный режим **не меняет данные, порядок, временные окна и условия активации действий** и не делает непроверенную ротацию `optimal`. В WuWa кнопка компактного режима отсутствует и исходная верстка не затрагивается. Развернутое описание при тапе по отдельному действию намеренно не включено в этот PR; при необходимости добавляется отдельной доступной интеракцией, без конфликтов с отметкой этапа.


**Исключение Endfield (визуальное, 2026-11-03):** Endfield `book.game==='arknights-endfield'` не использует чеклист выполнения. У него не отображаются `#reset`, `.progress-wrap` и `.complete`, а при навигации по этапам не читаются/записываются `done:*`. Сохраняется только индекс `at:*` для `По шагам` и выбор прочих настроек. Старые legacy done-ключи Endfield сохраняются в localStorage без удаления. WuWa сохраняет полноценное отслеживание прогресса. В компактном режиме Endfield заголовок этапа — одна строка `NN / NN · краткое название` без большого портрета и `stage.sub`; в полном режиме показываются оригинальные `stage.title`, `stage.sub` и stage portrait. Краткое имя получается удалением префикса TC и `N.` из `stage.title` когда он есть; для неизвестного формата сохраняется исходное имя.
